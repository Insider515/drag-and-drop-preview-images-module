# drag-and-drop-preview-images-module

Зона перетягування зображень із попереднім переглядом: фронтенд-віджет без залежностей
і серверний обробник завантаження без фреймворка.

Киньте на неї файли або виберіть їх звичним способом — кожен з'явиться мініатюрою
з розміром і кнопкою, щоб прибрати його назад. Зображення заповнюються по черзі, у міру
декодування, тож велика вибірка показує першу мініатюру одразу, а не сітку порожніх
квадратів. Без серверної адреси віджет лишається звичайним полем форми: файли їдуть
разом із формою, і бекенд не бачить різниці. Дайте адресу — і він надсилає їх сам,
зі смугою поступу та робочою кнопкою скасування.

Про що він дбає:

- **Файл — це те, що кажуть його байти.** Ім'я й тип, які повідомляє браузер, — це
  здогад операційної системи за розширенням; перейменувати виконуваний файл на `.png`
  достатньо, щоб обдурити обидва. Обидві половини читають натомість перші байти.
  Перевірка на клієнті існує, щоб пояснити причину користувачеві; вирішує серверна, бо
  все, що доступне через HTTP, можна надіслати curl-ом узагалі без браузера.
- **Сервер відхиляє імена, а не виправляє їх.** Вихід за межі теки в будь-якому
  написанні, нульові байти, зарезервовані імена Windows, крапки в кінці — ім'я, яке
  доводиться переписувати, щоб зробити безпечним, зазвичай належить спробі зламу.
- **Нічого недописаного не лишається.** Кожне завантаження йде під тимчасовим іменем
  і перейменовується, лише коли файл цілий, а обірваний запит прибирається за собою,
  замість лишати сміття на диску.
- **Форма з чужого сайту не може надіслати в цю адресу.** `multipart/form-data` не
  проходить preflight, тож без перевірки Origin будь-яка сторінка будь-якого сайту
  могла б завантажити файл під сесійною кукою користувача.

Три більші можливості є тоді, коли вони потрібні, і відсутні, коли ні. Кожна — це один
блок опцій; не вказали його — цей код не виконується взагалі:

- **[Стиснення перед надсиланням](#стиснення-зображень-перед-надсиланням)** — вписати в
  рамку, перекодувати з обраною якістю або прибрати метадані, не чіпаючи жодного пікселя.
  Усе на сторінці, тож зекономлені байти взагалі нікуди не їдуть.
- **[Завантаження під сеансом](#сеанси-хто-що-залив)** — тека на відвідувача й власник у
  кожній відповіді, за тим, чим ваш застосунок уже розрізняє людей, зокрема й
  неавторизованих.
- **[Перевірка на шкідливий вміст](#перевірка-завантажень-на-шкідливий-вміст)** — пошук за
  хешем у VirusTotal або власний сканер. Із сервера йде лише хеш, файл — ні.
- **[Повторна спроба після невдачі](#повторна-спроба-після-невдачі)** — автоматично або
  кнопкою, і лише для тих невдач, що про зв'язок, а не про файл.

Розмір і будова: 13 КБ JS і 2 КБ CSS у gzip на сторінці, нуль runtime-залежностей.
Серверна половина — одна функція `(req, res)`, яка монтується в Express, AdonisJS,
Fastify, Nest або голий `node:http`, і має єдину залежність — парсер multipart. Із нею
йдуть п'ять мов: англійська (типова), українська, іспанська, німецька й французька, —
а також світла й темна теми, де кольори, шрифти й розміри задаються під час підключення.

## Стан

У роботі, на npm поки не опубліковано. Доки цього не сталося, встановлюйте
з репозиторію:

```bash
npm install github:Insider515/drag-and-drop-preview-images-module
```

Або склонуйте й запустіть демо:

```bash
git clone https://github.com/Insider515/drag-and-drop-preview-images-module.git
cd drag-and-drop-preview-images-module
npm install
npm start          # збирає демо й піднімає його на http://127.0.0.1:5173
```

## Швидкий старт

### Як поле форми — без жодних змін на сервері

Не задавайте `endpoint` — і віджет лишиться тим, що замінив: `<input type="file">` із
попереднім переглядом. Файли йдуть разом із формою, і ваш наявний бекенд не помітить
різниці.

```html
<form action="/contact" method="post" enctype="multipart/form-data">
  <div id="images"></div>
  <button type="submit">Send</button>
</form>
```

```js
import { DropPreview } from 'drag-and-drop-preview-images-module';
import 'drag-and-drop-preview-images-module/style.css';

new DropPreview('#images', { name: 'images[]' });
```

### Самостійне завантаження

```js
const drop = new DropPreview('#images', {
  endpoint: '/api/upload',
  autoUpload: true,
});

drop.on('uploaded', ({ answer }) => console.log(answer.uploaded));
```

```js
// server
import express from 'express';
import { createUploadHandler } from 'drag-and-drop-preview-images-module/server';

const app = express();
app.use('/api/upload', createUploadHandler({ root: './uploads' }));
app.listen(3000);
```

## Звідки може взятися зображення

Чотири шляхи, і два останні ввімкнені за замовчуванням:

| | |
|---|---|
| Кнопка | Відкриває вибір файлів |
| Перетягування | У зону, з робочого столу або з іншого вікна |
| **Вставка** | Ctrl+V скриншота або зображення, скопійованого зі сторінки |
| **Камера** | Кнопка «Зробити фото» на телефоні |

### Вставка

```js
new DropPreview('#images', {
  paste: true,        // типово
});
```

`true` слухає сам віджет, тож вставка потрапляє в той, з яким людина щойно працювала. Це
єдине, що може бути правильним, коли на сторінці їх двоє, — і саме тому модуль так і не
реєструє нічого глобально.

На практиці: клацніть по зоні один раз, далі Ctrl+V. Для сторінки з одним віджетом, де
Ctrl+V має працювати без попереднього клацання:

```js
paste: 'document',
```

Це слухає всю сторінку — але не зазирає через плече: вставка в `<input>`, `<textarea>` чи
будь-що з `contenteditable` належить тому полю й лишається йому. Вставка, що не несе
файлів, теж лишається — звичайний текст вставляється туди, куди й цілився.

Вставлені зображення проходять усі ті самі перевірки. Скриншот, який насправді текстовий
файл, відхиляється так само.

`paste: false` не чіпляє нічого.

### Камера

```js
new DropPreview('#images', {
  camera: 'auto',           // типово
  capture: 'environment',   // задня камера; 'user' — фронтальна
});
```

Поруч із зоною з'являється кнопка **Зробити фото**, яка відкриває камеру одразу, а не
вибір файлів.

**`'auto'` означає «там, де вказівник грубий»** — телефон або планшет. На комп'ютері ця
кнопка відкривала б той самий діалог, що й сусідня, тобто була б шумом. `true` — показувати
скрізь, `false` — ніде. Браузер, у якого це не можна спитати, вважається комп'ютером.

**Це окремий `input`, і це не дрібниця реалізації.** Браузер, який шанує `capture`,
ігнорує `multiple`, бо камера повертає одне фото. Поставити `capture` на головний input
означало б відмовитись від вибору кількох зображень із галереї — а це те, чим є більшість
завантажень. Тому камера дістає власний input, а головний лишається недоторканим:

```
головний input   multiple, accept: усі формати, які знає розпізнавач
input камери     одне фото, accept: image/*, capture: environment
```

Кнопка стоїть в окремому рядку, а не разом із «Завантажити» й «Видалити все», бо той рядок
ховається, коли черга порожня, — а саме тоді хтось і хоче зробити фото.

## Опції віджета

```js
new DropPreview(target, {
  endpoint: null,         // POST here; null keeps it a plain form field
  name: 'images[]',       // form field name
  fields: null,           // extra form fields sent with an upload
  headers: null,          // object or function — for authorisation tokens
  credentials: 'same-origin',

  accept: [],             // MIME types; empty means every image format known
  allowSvg: false,        // SVG is XML that can carry script; opt-in
  limits: null,           // see below
  compress: null,         // стискати перед надсиланням; див. нижче
  retry: null,            // надіслати невдале завантаження ще раз; див. нижче
  filesPerRequest: 1,     // файлів в одному запиті; 0 — уся черга разом

  autoUpload: false,      // upload as soon as files are chosen
  showUploadButton: true,
  showClearButton: true,

  paste: true,            // Ctrl+V; 'document' слухає всю сторінку
  camera: 'auto',         // кнопка «Зробити фото», де вказівник грубий
  capture: 'environment', // яку камеру відкривати

  locale: null,           // 'en' | 'uk' | 'es' | 'de' | 'fr' | your dictionary
  theme: null,            // colours, fonts, metrics
  colorScheme: 'auto',    // 'auto' | 'light' | 'dark'
});
```

`target` — елемент або CSS-селектор.

### Обмеження

```js
new DropPreview('#images', {
  limits: {
    maxFileSize: 10 * 1024 * 1024,   // bytes per file
    maxFiles: 20,                    // files in the queue
    maxTotalSize: 100 * 1024 * 1024, // bytes for the whole queue
    maxPixels: 50 * 1024 * 1024,     // pixels a preview may decode
  },
});
```

`maxPixels` — не про охайність. PNG на 30 КБ може оголосити 40000×40000 і коштувати
кілька гігабайтів після декодування — вкладка помре ще до будь-якого завантаження.
Розміри відомі лише після того, як браузер розібрав заголовок, тому перевірка
відбувається під час побудови перегляду, і файл поза межею відкидається з поясненням.

### Методи й події

```js
await drop.add(fileList);        // same checks as picking them by hand
drop.remove(id);
drop.clear();
await drop.upload();
drop.cancel();
drop.destroy();

drop.files;                      // the queue, as plain objects
drop.totalBytes;
drop.busy;

drop.on('change',   ({ files }) => {});
drop.on('rejected', ({ rejected }) => {});   // [{ file, code, detail }]
drop.on('uploaded', ({ answer, files }) => {});
drop.on('error',    ({ error, code, message }) => {});
```

`on()` повертає функцію відписки.

Відмова несе `code`, а не речення, — на ньому можна розгалужуватись. Щоб показати її
людині, `drop.describeError(code, detail)` перетворює код на текст активною мовою.

## Мова

```js
new DropPreview('#images', { locale: 'de' });
```

Приймається `'en'`, `'uk'`, `'es'`, `'de'`, `'fr'` або повний тег, чия основа збігається
з однією з них: `'de-AT'` дасть німецьку. Нерозпізнане значення дає англійську, а не
помилку.

Множина рахується за правилом мови — українська має три форми, решта дві — а одиниці
розміру стають місцевими (`1.5 Ko` у французькій). На корені віджета проставляється
атрибут `lang`.

### Своя мова

Неповний словник — нормально: усе, чого в ньому немає, береться з англійської.

```js
import { DropPreview, PLURAL_RULES } from 'drag-and-drop-preview-images-module';

new DropPreview('#images', {
  locale: {
    id: 'sv',
    name: 'Svenska',
    tag: 'sv',
    plural: PLURAL_RULES.default,
    strings: {
      'drop.button': 'Välj filer',
      'drop.hint': 'eller dra dem hit',
      'count.files': { one: '{n} fil', other: '{n} filer' },
    },
  },
});
```

Готові словники — звичайні експорти (`import { en, uk } from '…'`), а в репозиторії
лежать у `src/locales/` — по одному простому об'єкту на мову. Тест стежить, щоб набір
ключів у всіх п'яти збігався, і відхиляє переклад, у якому з'явився підстановник, якого
немає в англійській.

## Оформлення

Нічого не передали — віджет виглядає так, як у демонстрації.

```js
new DropPreview('#images', {
  colorScheme: 'auto',      // 'auto' follows the system; 'light'/'dark' force it
  theme: {
    font: "'Inter', system-ui, sans-serif",
    fontSize: '15px',
    radius: '2px',
    tileSize: '140px',
    gap: '16px',
    dropHeight: '160px',

    colors: { accent: '#7c3aed', accentHover: '#6d28d9' },
    light: { bg: '#fffdf7', text: '#2b2415' },
    dark: { bg: '#0b1020', accent: '#a78bfa' },
  },
});
```

`colors` діє в обох схемах, `light` і `dark` його уточнюють. Оформите лише світлу — темна
лишиться з вбудованими кольорами, і світлий фон уночі не з'явиться.

**Кольори:** `bg`, `bgSubtle`, `bgSunken`, `border`, `borderStrong`, `text`, `textMuted`,
`accent`, `accentHover`, `accentSoft`, `accentContrast`, `danger`, `dangerHover`,
`success`, `warning`, `shadow`, `overlay`.

**Шрифти й розміри:** `font`, `fontSize`, `radius`, `radiusLarge`, `tileSize`, `gap`,
`dropHeight`.

Невідомий ключ кидає помилку, а не ігнорується. Ключ, що починається з `--`, проходить
наскрізь — для змінної, якої в переліку ще немає. Значення перевіряються: те, що могло б
закрити правило й відкрити своє (`;`, `}`, `url(`, коментарі), відхиляється — це важить,
якщо кольори у вас приходять від ваших користувачів.

Тема діє на один віджет, тож два на сторінці можуть виглядати по-різному.

## Куди можна змонтувати сервер

`createUploadHandler()` повертає звичайну функцію `(req, res)` над власними об'єктами
Node. `basePath` — префікс, який треба відрізати, коли хост не переписує `req.url` сам:
Express переписує, Adonis і `node:http` — ні.

```js
// Express
app.use('/api/upload', createUploadHandler({ root: './uploads' }))

// AdonisJS
const files = createUploadHandler({ root: app.makePath('uploads'), basePath: '/api/upload' })
router.any('/api/upload/*', ({ request, response }) => files(request.request, response.response))

// Fastify
fastify.all('/api/upload/*', (req, reply) => files(req.raw, reply.raw))

// bare node:http
http.createServer(files).listen(3000)
```

### Опції обробника

```js
createUploadHandler({
  root: './uploads',        // required; the one directory files may land in
  basePath: '',             // prefix to strip from the URL
  field: 'images[]',        // поле форми, яке читати — типове для віджета

  accept: [],               // MIME types; empty means every image format known
  allowSvg: false,
  onConflict: 'rename',     // 'rename' | 'refuse' | 'overwrite'
  rename: null,             // (name, { type }) => string — choose the stored name

  limits: {
    maxFileSize: 10 * 1024 * 1024,
    maxFiles: 20,
    maxRequestSize: 100 * 1024 * 1024,
    maxPixels: 50 * 1024 * 1024,      // пікселів, які може заявити зображення; 0 вимикає
    minFreeSpace: 64 * 1024 * 1024,
  },
  maxConcurrent: 8,         // uploads in flight; beyond that, 503

  allowedOrigins: undefined, // same-origin only by default; false disables the check
  authorize: (req, ctx) => true,
  onWarning: (message, detail) => {},
});
```

### Що повертається

```json
{
  "uploaded": [{ "name": "photo.png", "original": "photo.png", "size": 1024, "type": "image/png" }],
  "failures": [{ "name": "evil.png", "code": "NOT_AN_IMAGE", "error": "…", "params": null }],
  "fields": { "album": "holiday" }
}
```

Один поганий файл не валить пакет. Клієнту повідомляють, які не пройшли і чому, а решта
лишається.

### Тільки частина, що зберігає

`UploadService` робить роботу з файловою системою і нічого не знає про HTTP — для
фреймворка, який розбирає multipart сам:

```js
import { UploadService } from 'drag-and-drop-preview-images-module/server';

const service = new UploadService({ root: './uploads' });
const stored = await service.store(filename, readableStream);
```

## Стиснення зображень перед надсиланням

Вимкнено за замовчуванням. Вмикається блоком `compress` на віджеті:

```js
new DropPreview('#images', {
  compress: {
    maxWidth: 128,
    maxHeight: 128,
    quality: 'auto',
  },
});
```

Приберіть блок — і файли стають у чергу такими, якими прийшли. Усе це відбувається на
сторінці через canvas, який у браузері вже є, тож до збірки нічого не додається, а
зекономлені байти взагалі нікуди не їдуть.

### Що можна чесно обіцяти, а що ні

**Саме тут збірка без залежностей упирається в межу, тож прочитайте це перед вибором
налаштувань.**

| | Чи є тут | |
|---|---|---|
| Зміна розміру | **так** | Це вміє canvas |
| Стиснення з втратами | **так** | `toBlob` приймає якість |
| Видалення метаданих | **так, і точно** | Зображення копіюється байт у байт; прибирається лише EXIF, XMP, IPTC, коментарі й позначки часу |
| Стиснення **без втрат** | **ні** | Стиснути JPEG, не чіпаючи пікселів, можна лише кодеком, а кодек — це залежність |

Тому `quality: 'lossless'` тут означає **лише метадані**. Це не менший перекодований файл,
і модуль не вдаватиме інакше: на цьому шляху він взагалі не торкається canvas, бо canvas
декодує в пікселі й кодує знову, а для JPEG це щоразу трохи втрачає — навіть за якості 1.

Самі лише метадані варті більшого, ніж здається. Фотографія з телефона зазвичай несе
кілобайт налаштувань камери й GPS, а ще вбудовану мініатюру на десятки кілобайтів. Усе
невидиме, усе завантажується, а дещо — де знято — ніхто публікувати не збирався.

### `quality: 'auto'` — це 0.85

П'ятнадцять відсотків від верху шкали, і це те, що «не більше ніж на 15%» може чесно
означати, коли порівнювати немає з чим. Це регулятор кодувальника, а не виміряна різниця
для ока — виміряти її тут нічим, бо для цього потрібен кодек.

Хочете інакше — ставте число: `quality: 0.6`.

**На PNG це не впливає.** У PNG немає регулятора якості; браузер ігнорує аргумент. Щоб
зменшити PNG, змініть розмір або формат:

```js
compress: { maxWidth: 1600, format: 'image/webp' }   // зазвичай велика економія
```

### Налаштування

| Налаштування | Типове | Що робить |
|---|---|---|
| `maxWidth`, `maxHeight` | — | Рамка, у яку вписати. Досить і чогось одного |
| `fit` | `'contain'` | `'contain'` вписує в рамку, `'cover'` заповнює її |
| `quality` | `'auto'` | `'auto'` (0.85), число або `'lossless'` (лише метадані) |
| `format` | `'auto'` | `'auto'` лишає формат; або `image/jpeg`, `image/png`, `image/webp` |
| `stripMetadata` | `true` | Прибрати EXIF, XMP, IPTC, коментарі |
| `skipIfLarger` | `true` | Лишити оригінал, якщо новий файл насправді не менший |

Зображення, яке вже вміщається в рамку, лишається свого розміру — збільшення додає байтів
і вигадує деталі, яких не було.

### Три речі, яких воно не робитиме

**Не надішле вам більший файл.** PNG просто з оптимізатора зазвичай менший за будь-що, що
canvas зробить із тих самих пікселів, тож результат вимірюється і відкидається, якщо
програв. Вимикається через `skipIfLarger: false`, якщо вам важливіший єдиний формат.

**Не покладе ваші фотографії набік.** Камери телефонів записують, як їх тримали, в тег
EXIF, і браузери повертають зображення за ним. Прибрати цей тег — покласти кожне
портретне фото набік. Тому на шляху «лише метадані» EXIF із орієнтацією, відмінною від
«прямо», **лишається**; на шляху з перекодуванням його прибирають безпечно, бо canvas уже
вписав поворот у пікселі.

**Не втратить файл через невдале стиснення.** Кожна невдача — canvas кинув виняток,
браузер не вміє формат, зображення не декодувалося — закінчується надсиланням оригіналу
та подією `warning`, яку можна слухати:

```js
drop.on('warning', ({ code, error }) => console.warn(code, error));
```

### Чого це коштує

Стиснення йде після того, як файл пройшов ліміти, по одному зображенню за раз, і
використовує те саме декодоване зображення, яке вже зробив попередній перегляд — нічого не
декодується двічі, а декодована копія звільняється одразу після використання. Зверніть
увагу на порядок: файл, більший за `maxFileSize`, відхиляється **до** будь-якої спроби
його зменшити. Підніміть ліміт, якщо хочете приймати великі оригінали й стискати їх.

Черга повідомляє обидва розміри, тож економію можна показати:

```js
drop.on('change', ({ files }) => {
  for (const f of files) console.log(f.name, f.originalSize, '->', f.size);
});
```

## Повторна спроба після невдачі

Вимкнено за замовчуванням: одна невдача — і по тому, а причина лишається на плитці.

Вмикається блоком `retry`, і тоді невдале завантаження надсилається ще раз саме:

```js
new DropPreview('#images', {
  endpoint: '/upload',
  retry: { attempts: 3 },
});
```

Є ще кнопка й метод — вони працюють незалежно від того, є блок чи ні.

### Повторюється невдача, а не файл

Невдале завантаження буває двох різних видів, і ставитись до них однаково — це зробити
кнопку повтору або марною, або дратівливою:

| | |
|---|---|
| **Варто повторити** | `NETWORK`, `INTERNAL`, `BUSY`, `SCAN_FAILED`, `NO_SPACE` і будь-який `HTTP_ERROR` зі статусом 5xx |
| **Ні** | `TOO_LARGE`, `NOT_AN_IMAGE`, `TYPE_NOT_ALLOWED`, `INFECTED`, `INVALID_NAME`, `DENIED`, будь-який 4xx — і `ABORTED`, бо це було рішення самої людини |

Обрив зв'язку — про мить. Завеликий файл — про файл: надіслати його знову означає дістати
ту саму відмову, лише повільніше, і сховати причину під індикатором. Тому повторюється
лише перше, а друге лишається з поясненням на плитці.

У змішаній партії це помітно. Два файли впали: один тому, що шлюз відповів 502, другий
тому, що це текстовий файл з іменем `.png` — на дріт повертається лише перший.

### Налаштування

| Налаштування | Типове | Що робить |
|---|---|---|
| `attempts` | `3` | Скільки спроб усього, разом із першою |
| `delay` | `1000` | Мілісекунд до другої спроби |
| `backoff` | `2` | На скільки множиться кожне очікування |
| `maxDelay` | `30000` | Найдовше, яким може бути одне очікування |

З типовими значеннями паузи такі: **1 с, 2 с, 4 с, 8 с…** Кожна довша за попередню
навмисно: сервер, у якого погана хвилина, лишається таким якийсь час, а натовп браузерів,
що гатить у нього з однаковим інтервалом, робить із однієї поганої хвилини кілька.

Поки триває очікування, рядок стану про це каже — «Не вдалося — пробуємо ще раз (2 з 3)»
мовою віджета, — і **«Скасувати» обриває очікування одразу**. Скасування, яке нібито
ігнорують упродовж 30-секундної паузи, було б гірше за відсутність повтору взагалі.

### Масове завантаження переживає обрив

Файли їдуть **по одному на запит**, тож те, що долетіло, лишається долетілим. Покладіть
п'ятдесят фотографій в один запит — і зв'язок, обірваний на сорок дев'ятій, забере всі
п'ятдесят, а ті, що сервер уже записав, лишаться в нього на диску, тож повторне надсилання
партії залишить дублікати кожної з них. Заміряно, доки це не було типовою поведінкою:
десять файлів, обрив після шостого, повтор партії — п'ятнадцять файлів на сервері, п'ять
із них дублікати.

Тепер той самий обрив коштує одного файлу, який був у польоті:

```
12 у черзі, зв'язок обірвано після 7-го
  плитки: 7 done, 1 error, 4 ready
  на сервері: 7 файлів

натиснуто Retry
  на сервері: 12 файлів, без дублікатів
```

Файл зі статусом `done` не надсилається повторно ніколи — ні кнопкою «Завантажити», ні
«Повторити», ні чимось іще. Саме тому друга спроба дешева.

| Налаштування | Типове | Що робить |
|---|---|---|
| `filesPerRequest` | `1` | Файлів в одному запиті. Збільште, щоб проміняти надійність на меншу кількість звернень; `0` кладе всю чергу в один запит, як було раніше |

**Обрив зв'язку зупиняє обхід.** Решта файлів упала б так само, один за одним, і дивитись,
як сорок штук роблять це повільно, не допомагає нікому. А от **відмова** в одному файлі не
зупиняє: те, що третій не є зображенням, нічого не каже про четвертий.

Смуга поступу міряє всю чергу, а не запит у польоті — інакше вона відкочувалась би на
кожному файлі, — а рядок стану рахує файли, а не запити: «Завантажую 3 з 20».

### Кнопка і виклик руками

Кнопка **Повторити** з'являється поруч із «Завантажити», щойно щось впало з причини, яку
варто повторити, і зникає, коли повторювати нічого. Кнопка, яка є завжди, але зазвичай
марна, привчає на неї не зважати.

Те саме з коду:

```js
if (drop.retryable) await drop.retry();
```

`retry()` ставить у чергу лише те, що варто повторити, і надсилає; коли повторювати
нічого — повертає `null` і не робить жодного запиту.

### Як за цим стежити

```js
drop.on('retry', ({ attempt, of, delay, code }) =>
  console.log(`спроба ${attempt} з ${of} через ${delay} мс, після ${code}`));
```

Подія `error` спрацьовує **один раз**, після останньої спроби, а не після кожної.

### Чого воно не робить

Продовження відбувається між файлами, а не всередині одного. Фотографія на 10 МБ, що
обірвалась на 90%, починається спочатку — але лише вона, а не двадцять сусідніх. Щоб
продовжувати всередині файлу, сервер має тримати часткові завантаження й домовитись про
протокол для них, а це вже більша річ, ніж цей пакет.

## Сеанси: хто що залив

Вимкнено за замовчуванням. Точка не знає нічого про відвідувачів, усі файли падають в одну
теку, і хто що поклав — ніде не записано.

Вмикається блоком `sessions`. Ваш застосунок уже вміє відрізняти одного відвідувача від
іншого — за логіном або за кукою, яку носить неавторизований гість, — і це єдине, що
ви даєте:

```js
createUploadHandler({
  root: './uploads',
  sessions: {
    identify: (req) => req.session?.id ?? null,
  },
});
```

Тепер кожен сеанс дістає власну підтеку, а у відповіді сказано яку:

```
uploads/
  1f3c…a9/photo.png      ← Анна
  7b2e…04/photo.png      ← Борис, те саме ім'я, без зіткнення
```

```json
{ "owner": "1f3c…a9",
  "uploaded": [{ "name": "photo.png", "original": "photo.png", "size": 51234,
                 "type": "image/png", "owner": "1f3c…a9" }] }
```

Приберіть блок — і все повертається до однієї спільної теки. Більше нічого не змінюється.

### Три налаштування

| Налаштування | Типове | Що робить |
|---|---|---|
| `identify(req)` | — | Повертає id. Синхронно або асинхронно. Єдина обов'язкова частина |
| `scope` | `'directory'` | `'directory'` — тека на сеанс; `'label'` — одна спільна тека, лише позначка власника |
| `required` | `true` | Немає сеансу → 403 `NO_SESSION`. `false` — пускати такі запити в спільну теку |

`'label'` — коли файли лежать пласко, а власника ви пишете у свою базу:

```js
sessions: { identify: (req) => req.session.id, scope: 'label' }
```

Тоді id взагалі не потрапляє у файлову систему, тож може бути будь-яким — `user/42+ok`
підійде.

### Що модуль перевіряє і чого не робитиме за вас

За `scope: 'directory'` id стає іменем теки, а приходить він зазвичай із куки — тобто від
клієнта. Тому його перевіряють так само суворо, як ім'я файлу, і він має бути **вже**
придатним одиничним сегментом:

| Хук повернув | Що буде |
|---|---|
| `"1f3ca9"` | `uploads/1f3ca9/` |
| `"../escape"`, `".."`, `"/etc"`, `"a/b"` | 400 `INVALID_SESSION` |
| `"CON"`, `"x\0y"`, 300 символів | 400 `INVALID_SESSION` |
| `null`, `""` | 403 `NO_SESSION`, або спільна тека за `required: false` |
| хук кинув виняток | 500, причина йде в `onWarning`, а не клієнтові |

**Відхиляється, а не виправляється.** `/etc` не перетворюється тихцем на `etc`, а `a/b`
на `b` — саме так два різні сеанси опинилися б в одній теці. Якщо ваші id у base64 або
інакше не схожі на імена тек, зробіть із них хеш самі:

```js
identify: (req) => createHash('sha256').update(req.session.id).digest('hex').slice(0, 32),
```

Сеанс, який не вдалося встановити, зупиняє запит **до читання тіла**, тож відвідувач,
якому нема куди класти файли, не встигне надіслати мегабайти на ваш диск.

### На сторінці

Налаштовувати нічого: віджет шле запит із кукою, це вже робить `credentials: 'same-origin'`.
Два випадки варті окремого слова:

```js
// Точка на іншому домені, а сеанс живе в куці.
new DropPreview('#images', { endpoint: 'https://api.example.com/upload', credentials: 'include' });

// Сеанс їде токеном, а не кукою.
new DropPreview('#images', { endpoint: '/upload', headers: () => ({ Authorization: `Bearer ${token()}` }) });
```

`headers` приймає функцію, щоб токен читався в мить завантаження, а не в мить створення
віджета — це важливо для токена, який оновлюється.

### Іменування файлів за сеансом

`rename` тепер знає, для якого сеансу називає файл:

```js
rename: (name, meta) => `${meta.identity}-${Date.now()}-${name}`,
```

`meta.identity` дорівнює `null`, коли сеанси вимкнені або коли `required: false` пропустив
анонімного відвідувача.

## Перевірка завантажень на шкідливий вміст

Вимкнено за замовчуванням. Вмикається блоком `scan` із вашим власним ключем:

```js
createUploadHandler({
  root: './uploads',
  scan: {
    service: 'virustotal',
    apiKey: process.env.VT_API_KEY,
  },
});
```

Приберіть блок — і нічого не перевіряється. Залежностей не додається в жодному разі:
запит іде через `fetch` і SHA-256, які в Node уже є.

### Прочитайте це, перш ніж покладатися

**Надсилається лише хеш. Файл — ні.** Перевірка — це пошук SHA-256 файлу, тож із вашого
сервера не йде нічого, з чого можна відновити фотографію клієнта.

Саме цей вибір визначає можливості, і обмеження тут — головне:

> Воно впізнає шкідливе, про яке хтось уже повідомив. Воно не досліджує файл.
> Зразок, зроблений сьогодні вранці, йому невідомий.

Це варте того — відомі зразки і є більшістю того, що реально приходить, — і це **не**
заміна сканеру, який читає байти. Потрібен такий — передайте `check` і зверніться до
ClamAV через сокет або до того, що вже працює у вашій організації. Усе нижче стосується
і вашого сканера.

### Де саме це відбувається

Після того, як байти лягли на диск під тимчасовим випадковим іменем, і **до** того, як
файл дістав справжнє. Відхилений файл ніколи не існував під іменем, яке щось могло б
віддати, а його тимчасова копія видаляється. Файл, відхилений раніше з іншої причини —
не той тип, завеликий — до сканера взагалі не потрапляє й не коштує запиту.

### Налаштування

| Налаштування | Типове | Що робить |
|---|---|---|
| `service` | — | `'virustotal'`, єдиний вбудований |
| `apiKey` | — | Обов'язковий для цієї служби |
| `check(file, signal)` | — | Ваш власний сканер; отримує `{ sha256, name, type, size }` |
| `onUnknown` | `'accept'` | Що робити з файлом, якого база ніколи не бачила |
| `onError` | `'reject'` | Що робити, коли сама перевірка не вдалася |
| `timeoutMs` | `5000` | Скільки може тривати одна перевірка |

**`onUnknown` типово `accept`**, бо майже нічого з того, що завантажує звичайна людина,
ніколи не потрапляло до баз шкідливого ПЗ. `'reject'` відхиляв би майже кожне справжнє
фото.

**`onError` типово `reject`** — із протилежної причини. Якщо ви попросили перевірку, а
вона не відбулася, прийняти файл усе одно означає вважати себе захищеним, не будучи ним, —
і на екрані ніщо про це не скаже. Ставте `'accept'`, якщо волієте, щоб завантаження
працювали крізь аварію, розуміючи, чим платите.

### Аварія, яку ви справді зустрінете

Безкоштовний тариф VirusTotal дозволяє **чотири запити на хвилину**. Понад це він
відповідає 429, а з типовим `onError` це означає відмову `SCAN_FAILED`, доки хвилина не
мине. На публічній формі це черга роздратованих людей, тож перш ніж вмикати всерйоз:
подивіться ліміт свого тарифу, тримайте `maxFiles` помірним або сховайте перевірку за
власну чергу через `check`.

### Що бачить відвідувач

| Код | HTTP | Повідомлення мовою віджета |
|---|---|---|
| `INFECTED` | 422 | Файл позначено як шкідливий |
| `NOT_SCREENED` | 422 | Файл не вдалося перевірити (лише за `onUnknown: 'reject'`) |
| `SCAN_FAILED` | 503 | Перевірка недоступна, спробуйте ще раз |

Усі три перекладені п'ятьма мовами. Чому перевірка не вдалася — хибний ключ, ліміт
запитів, тайм-аут — іде в `onWarning`, а не клієнтові: ключ API чи назва внутрішньої
служби не для стороннього ока.

### Власний сканер

```js
scan: {
  check: async ({ sha256, name, type, size }, signal) => {
    const response = await fetch('http://scanner.internal/lookup', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify({ sha256 }),
      signal,                       // шануйте його, інакше timeoutMs не врятує
    });
    const { infected } = await response.json();
    return { verdict: infected ? 'malicious' : 'clean' };
  },
}
```

Повертайте `{ verdict }` зі значенням `'clean'`, `'malicious'` або `'unknown'` і за
бажання `detail`, який поїде клієнтові як `params` помилки. Будь-що інше вважається
збоєм і обробляється за `onError` — сканер, що відповів нісенітницею, ніколи не буде
прочитаний як «чисто».

## Безпека

Наскрізний принцип: **вирішують власні байти файлу, і сервер вирішує ще раз.**

**Розпізнавання.** `File.type` браузер бере з відповідності розширень в операційній
системі, тож перейменувати `payload.exe` на `photo.png` достатньо, щоб він назвався
`image/png`. Обидві сторони натомість читають перші байти. Клієнтська копія існує, щоб
пояснити людині причину; сервера — щоб мати вагу, бо все, що досяжне по HTTP, можна
надіслати curl і взагалі без браузера.

**SVG — лише за запитом.** Це єдиний формат зображення, який є XML і може нести скрипт.
Решта приймається за замовчуванням; цей треба попросити окремо.

**Імена.** Відхиляти, а не лагодити. Вихід за межі в будь-якому написанні, нульові байти,
символи, щодо яких файлові системи не згодні, кінцеві крапки й пробіли, зарезервовані
імена Windows — усе це відхиляється, а не переписується: ім'я, яке треба переписати, щоб
воно стало безпечним, зазвичай належить спробі. Шлях із завантаження теки вкорочується до
останнього сегмента ще до всього цього.

**Утримання в межах.** Куди потрапить файл, перевіряється двічі: лексично й проти
розв'язаного кореня. Жодної з перевірок окремо не досить — друга ловить символьне
посилання, підкладене в теку завантажень і скероване на `/etc`.

**Запис.** Кожен файл іде під тимчасовим іменем і перейменовується лише після успіху, тож
обірване завантаження не лишає обрізаного файлу під справжнім іменем. Остаточне ім'я
займається через `O_EXCL`, тож «чи вільне» і «зайняти» — одна операція; інакше два запити
з однаковим іменем пройшли б перевірку обидва, і один файл зник би.

**Міждоменні запити.** `multipart/form-data` — *простий* запит: preflight для нього не
робиться, тож звичайна `<form>` на будь-якому сайті могла б відправити сюди файли під
сесійною cookie користувача. Перевірка Origin це закриває. Запит зовсім без браузерних
заголовків — curl, виклик між серверами — пропускається.

**Обмеження** рахуються за фактично отриманими байтами, а не за `Content-Length` — це
твердження відправника, а в chunked-запиті його немає взагалі.

**Заявлений розмір.** PNG на 30 КБ може сказати, що він 40000×40000: тридцять кілобайтів на
дроті й шість гігабайтів, щойно щось його декодує. Браузер такі відхиляє, але браузер — не
те, чим користується зловмисник: curl надсилає такий файл повз перевірку, яка не виконується.
Тому сервер сам читає розміри із заголовка, нічого не декодуючи, і відхиляє файл ще під час
передавання. Стелю задає `limits.maxPixels`, типово 50 мегапікселів; `0` вимикає перевірку.

TIFF тримає каталог після пікселів, а JPEG із великою вбудованою мініатюрою може відсунути
свій заголовок кадру за межі того, що тримається в пам'яті. Обидва вимірюються з готового
тимчасового файлу, до того як він дістане справжнє ім'я. Формат, розмір якого прочитати не
вдалося, пропускається — щоб відсутній парсер не перетворився на зламану точку прийому.

**У DOM.** Нічого не збирається конкатенацією рядків в `innerHTML`; у помічника, яким
користується віджет, такої лазівки немає. Файл на ім'я `<img src=x onerror=alert(1)>.png`
малюється як цей текст і більше ніяк.

### Чого він не робить

- Не автентифікує, а частоту обмежує лише стелею одночасних завантажень — обмеження на
  клієнта ставиться перед ним.
- **Не перевіряє на шкідливий вміст, доки ви це не ввімкнете**, а ввімкнути можна пошук за
  хешем: він упізнає зразки, про які вже хтось повідомив, і не досліджує файл. «Це
  справжнє зображення» — не те саме, що «це безпечне зображення».
- **Не обробляє зображення, доки ви це не ввімкнете.** Без блоку `compress` нічого не
  перекодовується, не масштабується і не очищається, а EXIF — включно з координатами
  GPS — зберігається як прийшов.
- Не досліджує самі пікселі: розміри читаються із заголовка — саме з того, чому повірив би
  декодер, — але ніщо тут не декодує зображення, щоб переконатися, що воно таке і є.
- `server/standalone.js` — сервер для розробки без жодної автентифікації. Він не входить
  до npm-пакета.

### Що можна покрутити в демо

Сторінка демо — не частина пакета; вона існує, щоб кожну опцію можна було ввімкнути й
побачити, а не прочитати про неї:

| Кнопка | Що показує |
|---|---|
| Language, Theme, Custom palette | Мова, схема, власні кольори — усе без перезавантаження |
| SVG | Як виглядає відмова, коли формат не дозволено |
| Compress | `off`, `lossless` (лише метадані), `auto` (0.85), `0.6`, `0.3` |
| Resize | `off`, 1920, 1024, 512, 128×128 px |
| Malware check | Вмикає перевірку на сервері |
| Auto retry | Три спроби зі зростаючою паузою замість однієї |
| Paste | Усередині віджета, на всій сторінці або вимкнено |
| Camera button | Примусово показує кнопку, щоб її було видно на комп'ютері |
| Break the next upload | Наступне завантаження дістане 503 один раз, щоб побачити повтор |
| Upload history | Прибирає панель історії — вона належить сторінці, не віджету |

Історія показує обидва розміри, тож економію видно одразу:

```
change: 1 file(s), 6.8 KB — was 783.1 KB, saved 776.4 KB (99%)
  photo.jpg: 783.1 KB -> 6.8 KB
```

**Перевірка на шкідливі файли в демо — симуляція.** Щоб демо не вимагало акаунта й ключа
API (і щоб нічиї фотографії не їхали до третьої сторони), вона позначає як шкідливий
будь-який файл, в імені якого є `virus`. Перейменуйте фото на `photo-virus.jpg`, увімкніть
перевірку, натисніть «Завантажити» — і побачите відмову. Справжня — це
`scan: { service: 'virustotal', apiKey }`.

## Обмеження

- Тільки зображення. Таблиця розпізнавання знає десять форматів; решта відхиляється
  свідомо.
- Перегляд — це `background-image` на div, тож анімований GIF або WebP анімується в плитці
  так, як вирішить браузер; кадри не витягуються.
- Стиснення робить canvas браузера, тож *стиснення без втрат* тут немає: стиснути JPEG,
  не чіпаючи пікселів, можна лише кодеком, а кодек — це залежність. Видалення метаданих
  точне; усе інше перекодовує.
- Розміри читаються із заголовка, а не вимірюються: файл, що заявляє скромний розмір, а
  містить щось інше, буде збережено. Перевірка зупиняє протилежний і значно корисніший
  випадок — малий файл, що заявляє величезний.
- Черга тримається в прихованому input через `DataTransfer`; його підтримують усі сучасні
  браузери, але запасного шляху немає — без нього файли не поїдуть зі звичайною формою.
- HEIC і AVIF розпізнаються й завантажуються, але браузер, який їх не декодує, покаже
  порожню плитку; перетворення на сервері немає.
- Завантаження — один запит на всю чергу. Розбиття на частини немає, тож велика черга на
  поганому зв'язку — це «усе або нічого».
- Віджет використовує container queries і `:has()` — потрібен браузер 2023 року або новіший.
- Node 18+.
